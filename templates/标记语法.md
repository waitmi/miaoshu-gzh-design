# 标记稿语法（.gzh.md）

标记稿 = 原文正文 + 少量排版标记。**原文段落一字不改**，排版只往里加三类东西：元信息、章节标题、`:::` 指令块（卡片/表格/数据条等）。
构建：`python3 scripts/build.py <主题id> 文章.gzh.md --src 原文.md`。

## 1. 元信息（文件开头，`@键 值`）

| 键 | 必填 | 说明 |
|---|---|---|
| `@title` | 是 | 文章标题（与原文一致） |
| `@tbr` | 否 | 标题断行：用 `/` 标断行处，去掉 `/` 后必须与 `@title` 完全一致，如 `保费差不到100块的重疾险，/赔的钱能差一半` |
| `@kicker` | 否 | 头图小字栏目，如 `条款释义 · 重疾多次赔` |
| `@date` | 否 | 期号日期，如 `2026.10.30` |
| `@type` | 否 | 文章类型（备注用，不显示） |
| `@basis` | 否 | ⑦测评擂台头图的「同口径」说明，如 `30岁 · 30万保额 · 保一辈子 · 30年交` |
| `@sample` | 否 | ⑤体检报告单头图的「送检项目」，如 `「保证续保20年」条款` |
| `@month` | 否 | ⑧选购清单头图的金色大月份，如 `11月` |
| `@sub` | 否 | ⑧选购清单头图副标题，如 `4类需求 · 7款示例产品` |
| `@en` | 否 | ⑧选购清单头图英文小字，如 `HEALTH INSURANCE CHECKLIST` |
| `@chiplead` | 否 | ⑧头图胶囊开头的蓝字，默认有 @month 时为「本月精选」，否则「本期清单」 |

## 2. 正文

- 普通段落：空行分段，原样粘贴原文。
- `## 标题`：章节标题（各主题自动编号：01 / PART 1 / ROUND 1 / 检查项目 01 / 红圈①…）。
- 行内标记（只加在原文文字上，不改字）：
  - `**文字**` 锚点：主色加粗。**全文 ≤5 处**，留给最关键的判断。
  - `++文字++` 关键词下划线，每段 0–1 处。
  - `==文字==` 高亮（荧光底/表格差异格）。

## 3. 指令块

```
::: 类型 参数1 | 参数2 | 参数3
块内容（原文段落，或 | 分隔的表格行）
:::
```

块内容里的原文段落同样一字不改；`|` 表格行、参数是排版新加的整理文字，**会被当作新增文字严格查禁用词**。

### 3.1 通用组件（8 套都能用）

| 类型 | 参数 | 内容 | 效果 |
|---|---|---|---|
| `case` | 标题 \| 标签 | 原文段落 | 客户来问 / 案卷 / 主诉卡 |
| `lead` | — | 原文段落 | 导语卡 |
| `key` | — | 原文段落 | 判据框 / 划重点 |
| `verdict` | — | 原文段落 | 判断线 / 体检结论 / 擂台结论 |
| `quote` | — | 原文段落 | 金句 |
| `clause` | 产品名 \| 承保说明 \| 引导语 | 条款原文；`?? 人话` 一行 | 条款原文卡＋人话 |
| `term` | 名词 | 原文段落 | 名词卡 / 便签 |
| `example` | 标题 | 原文段落 | 举例卡 |
| `warn` | 标题 | 原文段落 | 避坑 / 注意 / 易错 / 犯规提醒 |
| `table` | 标题 \| 注释 | `\| 表头1 \| 表头2 \|` 首行表头，其余数据行；差异格写 `==值==` | 对比表 |
| `bars` | 标题 \| 单位说明 | 每行 `名称 \| 数值`；行首 `==` 指定焦点 | 横向数据条 |
| `calc` | 标题 | 原文推演段落；`= 卡片标题`；`\| 标签 \| 大数字 \| 说明` | 算一笔账＋双数据卡 |
| `duo` | 标题 | 两行 `左标题 \| 说明`、`右标题 \| 说明` | 双栏对照 |
| `gates` / `steps` | — | 每行一条（原文段落） | 编号门槛 / 清单 |
| `end` | — | 固定 3 行：结尾第 1 句、第 2 句、按钮文字 | 结尾关注引导 |
| `products` | 分类名 \| 分类标签 \| 胶囊简称 \| #主色 | 见 3.3 | 产品列表（选购清单）：分类标题＋产品卡；⑧ 为彩色横幅完整版 |
| `disclaimer` | — | 免责文字，**必须含「以保险合同条款及核保结果为准」** | 免责 |

| ⑤ tijian | `chips` | 标题 \| 注释 | 每行 `\| 标签 \|`（红框异常标签） |

### 3.3 产品列表 `products`（选购清单）

```
::: products 百万医疗险 | 大额住院费用 · 补充医保 | 百万医疗
（可选）分类导语段落
# 示例产品A · 百万医疗险 | 示例
- 保障范围：一般医疗与重疾医疗分设额度……
- 适合人群 | 已有社保或医保……
# 示例产品B · 百万医疗险（家庭版） | 示例
- 家庭投保：支持夫妻、父母、子女同一张保单投保……
:::
```

- 参数：分类名（必填）、分类标签（右侧小字）、胶囊简称（⑧头图「简称 N款」用，缺省取分类名）、`#RRGGBB`（⑧分类主色，缺省 6 色轮换）。参数都是排版新加文字，严格查禁用词。
- `# 产品名 | 角标`：开一张产品卡；角标可省，虚构产品写「示例」。
- `- 标签：正文`（标签 ≤6 字且无标点时自动拆）或 `- 标签 | 正文`：卡内要点；不带标签就整句作正文。标签含「适合」的要点铺浅底高亮。
- 其他行：分类导语，排在产品卡之前。
- 要点正文和产品名应来自原文（spec 行内引用 `# <<3>> | 示例`、`- <<4>>`），原文覆盖比对会逐句核对。
- 文案只写「推荐 / 适合」，不写「最高 / 第一 / 唯一 / 排行榜 / 排名」。

## 4. 用 spec 拼标记稿（推荐，保证原文不被手滑改动）

先列出原文段落编号：`python3 scripts/compose.py --dump 原文.md`，再写 `文章.spec`：

```
@src 原文.md
@tbr 标题前半，/标题后半
@kicker 栏目 · 主题
@date 2026.10.30
@mark ++ 原文里要加下划线的一句
@mark ** 原文里要做锚点的一句
<<0-2>>

::: products 分类名 | 分类标签
# <<3>> | 示例
- <<4>>
:::

## 新加的章节标题

::: key
<<3>>
:::
```

`<<n>>` 独占一行时引用整段；也可嵌在行里（产品列表的 `# <<3>> | 示例`、`- <<4>>`）。

`python3 scripts/compose.py 文章.spec` → 写出 `文章.gzh.md`，并提示未引用的原文段落和未命中的标记。

## 5. 原文约定

- 原文为 Markdown：`# 标题` 行、`>` 引用行不计入正文；第一个单独一行的 `---` 之后视为内部记录（核查记录、自检等），不发布、不比对。
- 固定开头「大家好，我是喵叔。」和固定结尾三句照常保留，结尾三句建议放进 `end` 块。
